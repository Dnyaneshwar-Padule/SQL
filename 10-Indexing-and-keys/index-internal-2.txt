REAL WORLD SCENARIO
-------------------

Disk = 512 GB SSD
Usme:
    - Operating System
    - Personal files
    - Videos, Photos
    - Other applications
    - Aur Database bhi

Database ko poori disk nahi milti.
Database ek normal program ki tarah hi OS se space maangta hai.


-------------------------------------------------------
1) DATABASE DISK KO DIRECT CONTROL NAHI KARTA
-------------------------------------------------------

Database directly disk partition nahi karta.

Operating System karta hai.

OS ke paas hota hai:
    File System (NTFS, EXT4, APFS, etc)

Database bas:
    File create karta hai
    File ke andar pages manage karta hai

Example:
    /var/lib/mysql/dbname.ibd
    C:\ProgramData\MySQL\data\students.ibd

Yeh normal files hi hoti hain.

OS decide karta hai:
    Kaunse physical disk blocks use honge.


-------------------------------------------------------
2) DATABASE SPACE KAISA OCCUPY KARTA HAI?
-------------------------------------------------------

Database data ko file ke form me store karta hai.

Example:

Database folder:
    students.ibd      → table data + index
    teachers.ibd
    ibdata1           → system tablespace
    undo logs
    redo logs

Jab table badi hoti hai,
toh file size badhta hai.

Example:
    students.ibd = 10 MB
    teachers.ibd = 2 MB

Ye file system me regular files hain.


-------------------------------------------------------
3) OS DISK SPACE KAISE MANAGE KARTA HAI?
-------------------------------------------------------

File system disk ko blocks me divide karta hai.

Example:
    Block size = 4KB

Database jab file write karta hai:
    OS us file ko free disk blocks allocate karta hai.

Database ko pata bhi nahi hota ki actual disk pe kahan store hua.

Database ke liye:
    File = continuous logical space

Physical disk fragmentation OS handle karta hai.


-------------------------------------------------------
4) DATABASE KO KAISA PATA HAI KITNA SPACE USE KARNA HAI?
-------------------------------------------------------

Database normally:
    Auto-grow files use karta hai.

Example:
    Initial size = 10 MB
    Auto extend = 5 MB at a time

Jab file full hone wali hoti hai:
    Database OS se aur space maangta hai.

OS agar free space available hai:
    File size badha deta hai.

Agar disk full ho gaya:
    Database error throw karega:
        "Disk Full"
        "Out of space"
        "Cannot allocate extent"

Insert/update fail ho sakta hai.


-------------------------------------------------------
5) PARTITIONS KA KYA ROLE HAI?
-------------------------------------------------------

Do tarah ke partitions hote hain:

1) OS Disk Partition
   C:, D:, /home, /var

2) Database Table Partition
   Logical partitioning inside DB

OS partition:
    Database sirf us partition ke free space tak hi grow karega.

Database partition:
    Table ko logical pieces me divide karta hai
    (date wise, range wise, hash wise)
    Lekin sab ek hi disk pe bhi ho sakta hai.


-------------------------------------------------------
6) AGAR DISK FULL HO JAYE TO?
-------------------------------------------------------

Situation:

Disk usage = 100%

Database kya karega?

- New rows insert nahi honge
- Index split fail ho sakta hai
- Transaction fail ho sakta hai
- Corruption risk bhi ho sakta hai (agar logs write nahi ho paaye)

Isliye production systems me:
    Disk monitoring bahut important hota hai.


-------------------------------------------------------
7) LARGE DISKS (GB / TB) SCENARIO
-------------------------------------------------------

Suppose:
    1 TB disk
    Page size = 16KB

Total pages:
    (1 * 1024 * 1024 * 1024 * 1024) / 16384
    ≈ 67 million pages

Page number store karne ke liye:
    4 bytes enough (2^32 pages)

Isliye RowID ka page number field fixed size ka hota hai.

Large disk hone se:
    Page count badh jata hai
    Page number field bada ho sakta hai (engine design par depend)


-------------------------------------------------------
8) DATABASE FILE STRUCTURE (SIMPLIFIED)
-------------------------------------------------------

Disk (512GB)
    |
    |-- OS files
    |-- User files
    |-- MySQL folder
            |
            |-- ibdata1
            |-- students.ibd (50MB)
            |-- teachers.ibd (10MB)
            |-- logs (5MB)

Database ko sirf apne folder ke files ka pata hota hai.


-------------------------------------------------------
9) CLUSTERED STORAGE (IMPORTANT)
-------------------------------------------------------

InnoDB (MySQL) me:
    Primary key index hi table hota hai.

Matlab:
    Table data B-Tree ke leaf nodes me hi stored hota hai.

Alag heap + alag index nahi hota.

Isliye primary key physically rows ko order karta hai.


-------------------------------------------------------
10) FINAL IMPORTANT CONCEPT
-------------------------------------------------------

Database disk ko partition nahi karta.
Database file create karta hai.
OS disk manage karta hai.

Database ke andar:
    File → Pages → B-Tree → Rows

OS ke andar:
    Disk → File System → Blocks → Files


-------------------------------------------------------
FINAL MENTAL MODEL
-------------------------------------------------------

Operating System = landlord
Database = tenant
Disk = building

Database apne room (files) ke andar
apna furniture (pages, index, rows) arrange karta hai.

Agar building full ho gayi,
tenant kuch nahi kar sakta.
